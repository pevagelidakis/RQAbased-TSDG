# Method changelog (after pre-registration)

Changes to method settings made after `PREREGISTRATION.md` was frozen, with the reason. Thresholds in
`config.yaml → preregistered` are never changed.

| date | change | reason | evidence |
|---|---|---|---|
| 2026-10-15 | Linear terms of ψ now cover every lag in the delay buffer z = (y_t, y_{t-1}, …, y_{t-(m-1)τ}) (D = (m-1)τ+1 terms); the random-Fourier (Gaussian-kernel) part still acts on the Takens vector x = z[::τ] exactly as specified. For τ = 1 nothing changes. | AR(2) benchmark (smoke run) failed PACF, PSD, variance and koopman_freq: with τ = 3, m = 6 the state (y_t, y_{t-3}, …) omits y_{t-1}, so it is not Markov for an AR(2) and the one-step readout cannot reproduce the process. The generator already keeps the full buffer, so this adds no new information source, only lets the linear readout use it. Thresholds unchanged. | `results/smoke_ar2/run.log` (pre-change): "VERDICT … failing: ['pacf', 'psd', 'variance', 'koopman_freq']" |
| 2026-10-15 | MCMC run length set by precision instead of a fixed count: warmup 1000 (was 5000); each chain samples in chunks of 500 until its own min(bulk, tail) ESS over θ reaches 4000/4 (≥ 1000, ≤ 25,000 draws per chain, i.e. the original fixed length is now the cap); target_accept 0.80 (was 0.90; 0.90/0.95/0.99 remain the remediation ladder). Spectrum computed in 4 processes. Removed unused code (duplicate JAX fast-gradient, non-whitened model, `benchmark` profile). | User request to minimise compute without losing quality. MCMC was 81% of wall time (smoke AR(2): 670 of 830 s); a fixed 4×(5000+25000) run costs ~10 h at the measured ~22 likelihood+gradient evaluations/s. The posterior is 4-D and near-Gaussian (whitened Hessian eigenvalues 0.89–1.10), so 4× the ESS gate gives MCSE ≈ 1.6% of a posterior SD, and only 500 thinned draws are used downstream. Pre-registered gates (R-hat, ESS, divergences, E-BFMI) are unchanged; divergences in draws discarded by common-length truncation still count. target_accept affects efficiency, not exactness. | `results/smoke_ar2/run_meta.json` stage timings; Lorenz/Hénon whitened-Hessian check in this session |
| 2026-10-15 | **Reverted** the full-buffer linear terms (row 1); ψ is again exactly the specified [1, x, √(2/F)cos(Wx/s+b)] on the Takens vector. **Added** an embedding rule: if Cao's E2(d) is within 0.10 of 1 for every d (no detectable determinism, train data only), τ = 1, and m is re-selected by Cao at τ = 1. | With the buffer terms, the noise-free Lorenz benchmark (τ = 4, m = 4, D = 13 near-collinear lags) became a near-interpolating fit (σ ≈ 4e-6, β ≈ 6e10). A = Λ + βΦᵀΦ then had a condition number ~1e17: the Cholesky log-likelihood varied by ±41 nats under 0.01 perturbations and the Laplace initialisation failed (gradient norm 232). An exact QR evaluation would cost 4–5× per gradient (Householder QR 210–290 ms vs SYRK 18–25 ms here). The AR(2) failure is instead fixed at its cause: AMI delay selection serves attractor unfolding, which does not apply to a stochastic series, whose Markov state is consecutive lags. Deterministic series keep the spec's τ. | `results/bench_lorenz/run.log` (aborted run, Laplace line); likelihood probe in this session; AR(2): Cao notes "E2(d) ~ 1 for all d" in `results/smoke_ar2_prefix/run.log` |
| 2026-10-15 | Noise floor (nugget): σ_eff² = σ² + σ_min², σ_min = 1e-3 train-SD units (`model.sigma_floor`), used consistently in the likelihood, weight draws, EDMD regularisation, innovations and forecasts. θ and its prior are unchanged (log σ is the free part). | With the spec-exact dictionary, noise-free simulated Lorenz (m = 4) still drives the fit to σ ≈ 4e-5. A = Λ + βΦᵀΦ then exceeds float64 precision (Laplace gradient norm 4036, likelihood jitter of tens of nats), so neither the optimiser nor NUTS can work. A nugget is the standard remedy: it costs nothing per evaluation and is negligible for any data whose noise exceeds 0.1% of the SD. Real measurements always have such a resolution limit. | `results/bench_lorenz/run.log` (aborted run 2, Laplace line); test `test_noise_floor_value_and_gradient` |
